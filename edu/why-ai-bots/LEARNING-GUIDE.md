# AI 봇에게 일을 맡기기 전에

장표를 본 뒤, 실제로 무엇을 맡길지 판단하기 위한 보충 자료입니다. 기존 29장과 음성의 순서는 그대로 따릅니다. 아래 예시는 학습용이며 특정 제품에서 실행한 결과가 아닙니다. 개념 출처 확인일은 2026-10-05입니다.

## 읽고 나서 설명할 수 있어야 할 것

- 답변 생성에서 작업 위임으로 관심이 넓어진 이유
- 모델, 도구, 기억, 실행 환경이 맡는 서로 다른 역할
- 일을 맡길 때 정할 허용 범위, 중단 조건, 완료 기준
- 제품 발표와 내 업무에서 확인한 성능의 차이

## 3~8장 보충: 무엇이 달라졌나

장표의 챗봇·코파일럿·에이전트·지속형 봇은 이해를 돕는 구분입니다. 실제 제품은 여러 기능을 함께 갖습니다. 대화창이 있다고 답변만 하는 것도, 에이전트라고 모든 일을 끝내는 것도 아닙니다.

여기서 **에이전트**는 목표를 받은 모델이 도구와 실행 결과를 바탕으로 다음 행동을 고르는 시스템으로 봅니다. **워크플로**는 미리 정한 순서와 분기에 따라 일을 진행합니다. 둘은 함께 쓸 수 있습니다. 순서가 고정된 반복 업무는 워크플로가 더 단순할 수 있고, 조사 결과에 따라 다음 단계가 달라지는 일은 에이전트 방식이 도움이 될 수 있습니다. [Anthropic의 구분과 설계 지침](https://www.anthropic.com/engineering/building-effective-agents)

연표에서 주목할 변화는 모델의 문장 생성 능력만이 아닙니다. 도구 호출은 문장을 프로그램의 입력으로 연결했고, 컴퓨터 조작은 화면을 통한 작업 경로를 넓혔습니다. 다만 함수 호출을 제안하는 것과 실제 실행하는 것은 구분해야 합니다. 호출을 받아 권한을 확인하고 실행하는 주변 프로그램이 필요합니다. [OpenAI의 2023년 함수 호출 발표](https://openai.com/index/function-calling-and-other-api-updates/)

이 자료에서 보는 열광의 이유는 끝난 산출물을 받고 싶은 수요, 맥락을 이어 가는 편리함, 실행 환경과 접근성의 결합입니다. 이 설명은 장표의 해석 틀입니다. 발표 건수나 GitHub 스타만으로 실제 도입률과 생산성 향상까지 입증되지는 않습니다.

## 10·23장 보충: 한 번의 위임은 어떻게 도나

**모델**은 다음 행동을 고르고, **도구**는 검색·계산·파일 작업 등을 수행합니다. **실행 환경**은 도구가 작동하는 공간과 권한을 제공합니다. **기억**은 나중에 다시 참고할 정보를 남깁니다. 계획은 처음 한 번 적고 끝내기보다 실행 결과에 맞춰 바꿀 수 있어야 합니다.

기본 흐름은 목표 확인 → 계획 → 도구 실행 → 결과 관찰 → 수정 또는 종료입니다. 막히면 사람에게 묻고, 완료 조건이나 정해 둔 한도에 도달하면 멈춥니다. 이런 반복 구조와 중단 조건은 [Anthropic의 에이전트 설명](https://www.anthropic.com/engineering/building-effective-agents)에 제시되어 있습니다.

### 예시: 공개 행사 세 곳 비교하기

다음은 예약이나 결제 없이 연습하는 요청입니다. 시간과 횟수는 이 예시에서 정한 한도이며 제품 기본값이 아닙니다.

> 이번 주말 갈 만한 공개 행사 세 곳을 찾아 비교해 주세요. 공식 페이지를 우선하고, 날짜·장소·비용·출처 링크를 적어 주세요. 정보가 없으면 확인 불가로 남겨 주세요. 로그인, 개인정보 입력, 예약, 결제는 하지 마세요. 10분 안에 확인한 내용을 알려 주고, 같은 페이지가 두 번 실패하면 그 항목은 멈춰 주세요.

1. **목표 확인:** 지역과 날짜가 빠졌다면 먼저 묻습니다. 완료 기준은 세 행의 비교표와 각 항목의 근거입니다.
2. **계획:** 후보를 찾고 공식 페이지에서 일정과 비용을 확인합니다.
3. **실행·관찰:** 검색 결과 제목만 믿지 않고 해당 페이지의 날짜와 조건을 읽습니다. 서로 다른 회차의 정보를 섞지 않습니다.
4. **재시도·중단:** 일시적인 읽기 실패는 한도 안에서 다시 시도합니다. 접근 거부나 로그인이 필요하면 우회하지 않고 미확인으로 남깁니다. 후보가 부족하면 그 사실을 보고합니다.
5. **완료 확인:** 표의 날짜·장소·비용이 링크 내용과 맞는지 확인합니다. 요청한 파일이 있다면 실제로 열리는지도 확인합니다. 예약·결제가 실행되지 않았는지 확인하고 결과를 전달합니다.

봇의 “완료했어요”라는 말과 실제 결과는 별도로 확인합니다. 예약 업무라면 예약 기록, 파일 업무라면 생성된 파일처럼 환경에 남은 결과를 봐야 합니다. [Anthropic의 에이전트 평가 안내](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

## 11장 보충: 기억에도 한계가 있다

모델이 지금 읽는 대화 범위와 장기 저장된 메모는 다릅니다. 저장한 정보를 다시 가져오거나 대화를 요약하는 방식으로 연속성을 만들 수 있지만, 요약 과정에서 중요한 조건을 놓칠 수 있습니다. 기억 기능이 있어도 모든 대화를 그대로 이해하고 보존한다고 가정하면 안 됩니다. [Anthropic의 컨텍스트·장기 기억 설명](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

업무에서는 다음을 확인합니다.

- 무엇을 저장하며, 누가 읽을 수 있는가
- 바뀐 일정이나 선호를 어떻게 고치고 오래된 정보와 구분하는가
- 기억 삭제와 대화·파일·연결 계정 삭제의 범위가 각각 무엇인가

검색으로 문서를 다시 읽는 것, 장기 메모를 남기는 것, 모델 자체를 학습시키는 것은 서로 다른 기능입니다. 제품의 실제 저장·삭제 범위는 해당 서비스 문서에서 확인해야 합니다.

## 9·25~29장 보충: 승인과 격리는 따로 확인한다

자가호스팅은 운영자가 실행 환경을 관리한다는 뜻입니다. 내 서버에 설치했다고 자동으로 격리되지는 않습니다. OpenClaw는 샌드박스가 기본적으로 꺼져 있다고 안내하며, 별도의 실행 승인 기능도 제공합니다. 기존 원고의 “승인은 직접 구현”이라는 설명은 모든 기능을 새로 개발해야 한다는 오해를 줄 수 있어 이번 개정에서 바로잡았습니다. **운영자가 격리·도구 권한·승인 정책을 설정하고 확인한다**는 설명이 정확합니다. [OpenClaw 샌드박스](https://docs.openclaw.ai/gateway/sandboxing), [실행 승인](https://docs.openclaw.ai/tools/exec-approvals)

외부 문서나 웹페이지에 봇을 겨냥한 명령이 들어 있을 수도 있습니다. 읽어 온 자료의 문장을 사용자의 지시로 착각해 행동하는 위험을 프롬프트 인젝션이라고 부릅니다. 자료 읽기와 행동 권한을 구분하고, 메일 발송이나 구매 같은 단계에는 승인 경계를 둡니다. 도구 출력이 의도하지 않은 행동을 유도할 수 있다는 문제는 [OpenAI의 함수 호출 발표](https://openai.com/index/function-calling-and-other-api-updates/)에서도 다룹니다.

승인을 받을 때는 “계속할까요?”만 묻기보다 대상, 보낼 정보, 바뀔 내용, 비용과 되돌릴 수 있는지를 보여 주는 편이 좋습니다. 격리는 피해가 번질 범위를 줄이고, 승인은 특정 행동을 허락할지 판단하게 합니다. 어느 하나만으로 결과의 정확성까지 보장되지는 않습니다.

Dots는 비밀번호 변경을 사용자가 직접 처리하도록 안내합니다. 영구 삭제의 명시 승인과 구분해야 합니다. 이번 개정은 21·22장의 화면과 원고에도 이 차이를 반영했습니다. [Dots 통제 안내](https://learn.chatgpt.com/docs/dots/controls) (2026-10-05 확인)

## 21·22장 세부 조건: 화면에서 줄여 쓴 내용

장표에서는 네 질문과 핵심 조건을 크게 보여 줍니다. 아래는 같은 자료에 있던 세부 설명이며, 제품 상태를 추가로 재검증한 목록은 아닙니다.

### Dots의 실행과 통제

- 클라우드 작업은 내 기기가 꺼져도 이어집니다. 한 dot은 백그라운드 에이전트들에게 일을 나눠 병렬로 진행합니다.
- 연결한 내 컴퓨터를 쓰는 작업은 그 컴퓨터가 켜져 있고 ChatGPT 앱이 열려 있어야 합니다.
- 연결한 앱은 내 계정·권한 안에서 사용합니다. 클라우드 브라우저 로그인은 내 컴퓨터 브라우저와 별개입니다.
- 자동 심사는 계정·정보 공유 행동을 지시, 권한, 내 규칙, 기본 안전 요건과 대조합니다. Custom Rules로도 핵심 안전 요건은 끌 수 없습니다.
- 비밀번호 변경은 사용자가 직접 처리합니다. 영구 삭제는 명시 승인이 필요하고 저장 카드 구매도 승인을 받습니다. 안전 문제를 감지하면 작업이 정지될 수 있습니다.
- 일시 정지는 주 작업만 멈춥니다. 위임한 작업의 중단과 예약 취소는 별도로 확인해야 합니다.
- 완료 표시는 요청한 결과의 달성이나 전달까지 확인했다는 뜻이 아닙니다. 결과와 오류를 직접 검토합니다.
- Enterprise 워크스페이스는 기본 비활성 상태이며 관리자가 켭니다.

### 비교표를 읽을 때 남겨 둘 구분

Grok Bot의 Auto Review는 모델 기반 위험 평가이며 최소 권한을 대체하지 않습니다. Network Controls는 Enterprise 전용이고 해당 정책이 없으면 전체 허용이 기본입니다. 로컬 실행은 공식 문서에서 사용하지 않기를 권고합니다. 봇 사이의 환경 공유와 오프보딩도 확인합니다.

Muse의 Sentinel은 인터넷으로 나가는 길목인 egress를 중개합니다. Confidential VM의 출시 완료는 이 자료에서 확인하지 못했습니다. 9월 8일 미국 롤아웃과 9월 29일 미국·캐나다 이용 안내를 구분합니다.

Dots의 자동 심사와 Custom Rules는 앞의 두 제품과 같은 장치가 아닙니다. 로컬 연결 작업의 기기·앱 조건, 클라우드 작업의 지속, Enterprise 관리자 활성화를 각각 확인합니다.

용어: **자동 심사**는 행동이 규칙에 맞는지 시스템이 확인하는 단계, **Custom Rules**는 사용자가 직접 정하는 규칙, **명시 동의**는 사용자가 분명하게 허락하는 것입니다. **Sentinel**은 Muse의 외부 통신을 중개하는 통제 계층입니다.

근거는 기존 21·22장과 같습니다. [Dots 컴퓨터·앱 안내](https://learn.chatgpt.com/docs/dots/computers-and-apps), [Dots 통제 안내](https://learn.chatgpt.com/docs/dots/controls), 제품별 상세 근거는 [출처 기록](SOURCES.md)을 확인합니다.

## 14~22·28장 보충: 제품을 고를 때 볼 기준

장표의 제품별 날짜·가격·이용 지역·출시 예정 상태는 당시 공개 자료를 정리한 것입니다. 이 보충 자료를 추가했다고 모든 제품 정보를 오늘 기준으로 다시 검증한 것은 아닙니다. 이용 전에는 해당 공식 문서와 실제 계정 화면에서 확인합니다. 상세 근거와 기존 확인 범위는 [출처 기록](SOURCES.md)에 있습니다.

기업의 소개 문구, 확인 가능한 기능, 실제 업무의 성과는 구분해서 봅니다. “자율 실행”이라는 표현만으로 무인 운영을 결정하지 않습니다. 예산과 중단 기준을 정한 작은 작업부터 시험합니다.

| 기준 | 확인할 내용 |
|---|---|
| 품질 | 요청한 항목을 빠짐없이 채웠는가. 근거와 산출물이 맞는가. |
| 신뢰성 | 비슷한 일을 반복해도 성공하는가. 실패를 숨기거나 중복 실행하지 않는가. |
| 비용 | 모델·도구 사용료와 재시도 비용, 사람이 검토한 시간을 함께 봤는가. |
| 지연 | 평균뿐 아니라 오래 걸린 작업과 승인 대기 시간도 확인했는가. |
| 통제 | 허용 범위를 지켰는가. 중단·기록 확인·접근 회수가 가능한가. |

위 표는 학습용 점검 틀입니다. 반복 시도, 성공 기준, 실제 결과 검증과 비용·지연 측정의 필요성은 [Anthropic의 평가 안내](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)를 참고했습니다. 특정 제품의 점수나 순위를 뜻하지 않습니다.

전망도 같은 방식으로 읽습니다. 이용 지역 확대, 권한 통제 개선, 반복 업무의 성공률을 관찰할 수는 있습니다. 어떤 제품이 언제 보편화될지, 사람의 일을 얼마나 대체할지는 이 자료만으로 확정하지 않습니다.

### 답과 이유

1. 고정된 절차나 일반 프로그램으로 충분할 수 있습니다. 실행 중 판단과 경로 변경이 필요한지 먼저 봅니다.
2. 실제 서비스의 발송 기록과 수신 대상·내용을 확인합니다. 발송 기록만으로 상대가 읽었다고 단정하지 않습니다.
3. 안 됩니다. 외부 자료는 행동을 허락하는 주체가 아닙니다. 사용자가 승인한 범위 안에서만 진행합니다.
4. 안 됩니다. 설치 위치와 격리·권한 설정은 별개입니다.
5. 먼저 제한된 범위에서 반복 검증합니다. 실패 처리, 비용, 사람의 검토와 승인 지점을 정해야 합니다.
