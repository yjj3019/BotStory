# Why AI Bots — 교육 패키지 (AI 대항해 시대)

Notion 대본 32클립을 **슬라이드(장표) 레이아웃** HTML + 나레이션으로 묶은 교육 자료입니다.

- **형식**: 설명형 장표와 렌더링용 나레이션 32클립. 음성은 별도 제작하며 재생 시간은 새 음원을 만든 뒤 측정합니다.
- **자료 기준**: 2026-10-01 교육본 · 2026-10-05 개념·안전 설명과 재생기 개정
- **경로**: `edu/why-ai-bots/`

## 최소 구성 (기록 범위)
- `why-ai-bots.html` — 오프닝 + 29장(9장에 OpenClaw 사례 1화면 추가, 총 30화면) + 엔딩
- `narration.json` — 32클립 나레이션 (`lines[]` 유지)
- `slide-visible-copy.md` — 화면에 보이는 층 카피 (SCENES에서 자동 생성)
- `SOURCES.md` — 사실별 근거와 확인 범위, 개정 기록
- `LEARNING-GUIDE.md` / `learning-guide.html` — 작동 과정·위임 예제·기억 한계·평가 기준·확인 문제
- `audio-manifest.json` — 녹음 파일 해시·실측 길이·원고 해시와 재생 정책

실행에 필요한 `assets/bg`(배경 1종)와 `assets/photos`(CC 사진 9장, 크레딧은 `assets/photos/CREDITS.md`)를 함께 둡니다. 로고·인물 초상·제품 UI 스크린샷·미PASS 수치는 넣지 않습니다.

3. **설정값 세 개 (29장)** — 네트워크 정책 · 로컬 Never · 오프보딩.

## 학습 보충과 사실 개정

장표의 학습 보충 버튼이나 [학습 가이드](LEARNING-GUIDE.md)를 이용합니다. 작은 화면에서는 [HTML 가이드](learning-guide.html)를 권장합니다. 가이드는 워크플로와 에이전트의 구분, 도구 실행과 관찰·재시도·중단, 기억의 한계, 안전한 위임 예제와 확인 문제를 다룹니다.

- 3장: 제품 이름만으로 권한이나 작업 성공을 단정하지 않도록 수정했습니다.
- 9장①: 자가호스팅이 자동 격리를 뜻하지 않으며 OpenClaw에도 실행 승인 기능이 있음을 반영했습니다.
- 17·19·22장: Muse의 9월 8일 미국 롤아웃과 9월 29일 미국·캐나다 이용 안내를 구분했습니다. 요금은 기존 안내 재인용이며 공식 원문 재확인이 필요함을 표시했습니다.
- 25장: Moltbook 사고의 원인을 공개 키 자체가 아닌 RLS 접근 제어 설정 누락으로 바로잡았습니다.
- 21·22장: Dots의 비밀번호 변경은 사용자가 직접 처리하는 단계이며, 영구 삭제의 승인과 구분했습니다.

개념·해당 안전 문구는 공식 문서로 확인했습니다. 제품 전체의 요금·지역·계정별 제공 범위까지 오늘 기준으로 재검증한 것은 아닙니다. 이용 전 공식 문서와 실제 계정 화면을 확인하세요.

## 나레이션 파일과 기존 오디오

이번 납품 범위는 [나레이션 원고 패키지](narration-delivery/)입니다. 음성 렌더링은 사용자가 별도로 진행합니다.

- 32클립, 낭독문 16,325자, 문장별 465줄입니다.
- `clips/*.txt`는 읽을 말만 담은 UTF-8 파일입니다. 전체 읽기본과 발음표는 별도입니다.
- 렌더링 매니페스트는 순서·장표 대응·MP3 파일명·텍스트와 파일 해시를 제공합니다. 실제 재생 시간은 `null`입니다.
- HTML 낭독문, 원본 JSON, 패키지 JSON과 TXT는 같은 내용을 사용합니다.

기존 `audio/`의 MP3 32개와 크레딧 BGM은 보관했습니다. 나레이션 32파일의 과거 실측 합계 2611.272초는 새 원고의 러닝타임이 아닙니다. `audio-manifest.json`도 보관 음원임을 명시합니다.

원고 전체의 낭독 표기를 통일했으므로 **기존 32클립은 모두 자동 재생을 차단**했습니다. 현재는 원고를 표시하고, 앞·뒤 버튼으로 내용을 볼 수 있습니다. 브라우저 음성은 사용하지 않습니다. 새 녹음의 발화·누락·길이·화면 대응을 확인한 뒤 검증된 클립만 `PENDING_RECORDING_CLIPS`에서 해제해야 합니다. 파일을 덮어썼다는 사실이나 해시만으로 발화 일치를 증명할 수는 없습니다.

음성 생성·과금·청취는 이번 작업에 포함하지 않습니다. 원래 목소리의 정확한 공급자와 voice ID는 저장소에 기록되지 않아 재현을 보장하지 않습니다. 모든 클립을 같은 목소리와 설정으로 렌더링하는 방법은 패키지 README에 적었습니다.

## 수정·검증

HTML의 `OPENING_TEXT`, `SCENES`, `ENDING_TEXT`가 원고와 화면의 원본입니다. `narration.json`의 `lines`, `text`, `chars`와 화면 카피는 생성 파일입니다. 원고를 수정한 뒤에는 기존 오디오가 맞는지도 별도로 검토해야 합니다.

전제: Node.js 22 이상, Python 3, ffprobe(FFmpeg), Chromium. 개발 도구는 저장소 루트에서 설치합니다. 장표 열람 자체에는 설치가 필요 없습니다.

```bash
npm install
npm run sync           # 원고 JSON, 화면 카피, 학습 가이드 HTML 생성
npm run check:content  # 생성 파일의 누락·불일치 검사
npm run check:audio    # 녹음/원고 해시·파일 길이 검사 (발화 확인 아님)
npm test              # 위 검사와 모의 미디어/DOM 재생기 회귀 검사
npm run test:browser  # 허용된 Chromium 환경에서 화면 캡처·실제 로딩 검사
```

Chromium 경로가 다르면 `CHROMIUM_PATH`를 지정합니다. 오디오나 원고를 의도적으로 변경했다면 정합성을 확인한 다음에만 `python3 scripts/audio-manifest.py --write`로 기준을 다시 기록합니다. 이 명령으로 검사를 통과시키는 것만으로 음성 검증을 대체하지 마세요.

재생 중 버튼은 일시 정지와 이어 재생을 제어합니다. 앞·뒤 이동은 현재 음성을 중단합니다. 자세한 회귀 검사 범위와 실행 한계는 [개정 검토 기록](REVIEW-2026-10-05.md)에 있습니다.
