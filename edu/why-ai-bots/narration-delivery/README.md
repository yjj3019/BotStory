# BotStory 나레이션 원고

원래 교육 자료의 흐름과 32클립 순서를 유지하면서 낭독 문장·발음·사실 표현을 정리한 원고입니다. 음성 렌더링은 포함하지 않습니다. 특정 TTS 공급자나 목소리를 전제로 하지 않습니다.

## 파일 사용

- `clips/00-opening.txt`부터 `clips/31-ending.txt`: 한 파일당 한 음원으로 만들 실제 낭독문입니다. UTF-8, BOM 없음, 문장별 줄바꿈 형식입니다.
- `narration.json`: 클립 ID·제목·문장 배열·전체 텍스트·문자 수를 담은 원본과 동일한 JSON입니다. `text`는 `lines`를 공백 하나로 연결한 값입니다.
- `read-through.md`: 사람이 전체 흐름을 확인하는 읽기본입니다. 제목과 안내를 포함하므로 그대로 TTS에 넣지 마세요.
- `PRONUNCIATION.md`: 화면의 영문 표기와 원고의 한글 읽기 대응표입니다.
- `rendering-manifest.json`: 렌더링 순서, 입력 TXT, 대응 장표, 저장할 MP3 이름, 원고·파일 해시입니다. 재생 시간은 아직 알 수 없어 `null`로 두었습니다.
- `CONTENT-NOTES.md`: 주요 정정과 출처 확인의 한계입니다.

## 렌더링 순서

1. `rendering-manifest.json`의 `order` 순서로 TXT를 읽습니다.
2. 전체 클립에 같은 한국어 목소리와 속도·샘플레이트 등 설정을 적용합니다. 숫자가 같은 속도 설정이라도 엔진이 다르면 실제 속도가 같지는 않습니다.
3. 첫 클립으로 문장 쉼과 고유명사 독음을 확인한 뒤 나머지를 진행합니다.
4. 결과를 `targetMP3filename`과 정확히 같은 이름으로 저장합니다. 예를 들어 `03-scene.txt`는 `03-scene.mp3`가 됩니다.
5. 각 음원의 앞뒤 누락, 반복·절단, 고유명사, 긴 무음과 클리핑을 확인합니다. 실제 길이는 생성 후 측정합니다.

장 번호와 파일 번호는 항상 같지 않습니다. 9장에 화면이 두 개이므로 `09-scene`은 9장①, `10-scene`은 9장②, `11-scene`은 10장입니다. 오프닝은 `00-opening`, 엔딩은 `31-ending`입니다. 파일 이름을 장 번호로 다시 매기지 마세요.

## 저장소와 연결

장표는 `edu/why-ai-bots/why-ai-bots.html`이며, 검증한 음원의 저장 위치는 그 옆 `audio/`입니다. 기존 MP3는 이전 원고의 보관본으로 남겨 두었고, 이번 원고에 자동으로 재사용하지 않습니다. 새 음원을 넣는 것만으로 기존 보호 설정이 해제되지는 않습니다. 원고와 음원이 맞는지 확인한 뒤 장표의 `PENDING_RECORDING_CLIPS`에서 검증된 클립만 해제해야 합니다. 파일 해시는 내용이 바뀌었는지 확인하는 수단이며, 올바르게 발화했다는 증명은 아닙니다.

원고를 바꾸는 경우 저장소의 HTML 낭독문을 수정하고 `npm run sync`로 생성 파일을 갱신합니다. `npm test`는 텍스트·파일 매핑과 재생기 상태를 검사합니다. 음성 품질·청취·화면과의 실제 동기는 새 음원 생성 후 별도로 확인해야 합니다.

## 필수 길이: 새 나레이션 실측 30분 이상

이번 교육 자료는 **새로 만든 32개 나레이션 MP3의 합계가 최소 1,800초(30분)**여야 합니다. 29분 59.999초는 불합격이고, 30분 00초부터 길이 조건을 충족합니다. 현재는 미렌더링 상태이므로 이 조건을 충족했다고 인증하지 않았습니다.

렌더링 계획은 여유를 두고 32~35분 이상을 목표로 잡을 수 있습니다. 이는 추정 목표이며, 문자 수나 TTS 속도 숫자가 시간을 보장하지 않습니다. 듣기 편한 자연스러운 속도와 쉼을 유지하고 실제 결과를 측정합니다. 30분 미만이면 교육 설명을 보강하거나 적절한 자연스러운 속도로 다시 렌더링한 뒤 재측정합니다. 원고를 보강하면 원본과 해시도 함께 갱신해야 합니다.

크레딧 음악, 화면 전환 대기, 다른 음원, 과거 녹음 길이는 합산하지 않습니다. 조건을 맞추기 위한 인위적인 무음·음악 삽입이나 부자연스러운 늘이기도 허용하지 않습니다. 문장 사이 자연스러운 쉼은 낭독의 일부이며, 시간만 늘리기 위한 패딩과 구분해 청취합니다.

### 새 음원 수락 검사

저장소에 FFmpeg의 `ffprobe`와 Node.js가 있는 환경에서 실행합니다. 이 텍스트 ZIP 자체에는 검사 프로그램과 음원이 들어 있지 않습니다.

1. 새 음원만 모은 폴더에 매니페스트의 정확한 이름으로 MP3 32개를 둡니다. 크레딧 음악이나 다른 오디오는 넣지 않습니다.
2. 저장소 루트에서 `npm run verify:rendered-audio -- --audio-dir 새_MP3_폴더`를 실행합니다. 실제 MP3 스트림과 ffprobe 길이, 32개 파일 이름, 정본 JSON·클립 텍스트 해시를 검사합니다. 기존 보관 녹음과 같은 해시는 거부합니다. 합계가 1,800초 미만이거나 파일이 빠지면 실패합니다.
3. 길이만 통과한 경우에도 종료 코드는 실패이며 `NOT_CERTIFIED_SPEECH_REVIEW_REQUIRED` 상태로 측정 결과를 출력합니다. 이 결과의 파일·텍스트 해시를 보관하고, **32개 음원을 모두 들어** 원고 누락·추가·반복 여부, 발음, 음악 혼입, 인위적 무음 패딩을 확인합니다. 도구의 해시·길이 검사는 발화 내용을 자동으로 증명하지 않습니다.
4. 청취 결과를 별도 `speech-review.json`으로 기록합니다. 최상위 `sourceJSONSHA256`은 측정 결과와 같아야 합니다. `clips`는 같은 순서의 32개 항목이며 각 항목에 측정 결과의 `id`, `textSHA256`, `audioSHA256`과 확인을 마친 `canonicalSpeechVerified: true`, `narrationOnly: true`, `noArtificialPadding: true`를 넣습니다. 듣지 않은 항목을 true로 만들지 마세요.
5. `npm run verify:rendered-audio -- --audio-dir 새_MP3_폴더 --review speech-review.json`을 실행합니다. 실제 길이와 청취 기록의 해시가 모두 맞아야 통과합니다. 통과 표시는 제공된 청취 기록에 근거하며 도구가 직접 들었다는 뜻은 아닙니다. 이 검사는 파일 수정이나 재생 보호 해제를 수행하지 않습니다.

`npm test`에는 1,799.999초 실패·1,800초 통과, 누락 파일, 원고 해시 불일치, 보관 녹음 거부와 청취 확인 누락 검사가 포함됩니다. 테스트용 가짜 파일 검사가 통과해도 실제 교육 음원의 30분 충족을 의미하지 않습니다.

## 시간과 확인 범위

원고만으로 총 재생 시간을 확정하지 않습니다. 실제 길이는 목소리·속도·쉼·렌더링 결과에 따라 달라집니다. 과거 MP3의 실측 길이를 새 원고의 러닝타임으로 사용하지 마세요. 크레딧 배경 음악은 32개 나레이션 클립에 포함되지 않습니다.

이 패키지는 32개 원고의 순서·UTF-8·JSON/문장/텍스트 일치·장표 대응·SHA-256을 자동 검사한 결과물입니다. 음성 생성이나 실제 청취를 완료했다는 뜻은 아닙니다.
