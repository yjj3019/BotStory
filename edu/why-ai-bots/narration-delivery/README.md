# BotStory 나레이션 원고

원래 교육 자료의 흐름과 32클립 순서를 유지하면서 낭독 문장·발음·사실 표현을 정리한 원고입니다. 음성 렌더링은 포함하지 않습니다. 특정 TTS 공급자나 목소리를 전제로 하지 않습니다.

## 파일 사용

- `clips/00-opening.txt`부터 `clips/31-ending.txt`: 한 파일당 한 음원으로 만들 실제 낭독문입니다. UTF-8, BOM 없음, 문장별 줄바꿈 형식입니다.
- `narration.json`: 클립 ID·제목·문장 배열·전체 텍스트·문자 수를 담은 원본과 동일한 JSON입니다. `text`는 `lines`를 공백 하나로 연결한 값입니다.
- `read-through.md`: 사람이 전체 흐름을 확인하는 읽기본입니다. 제목과 안내를 포함하므로 그대로 TTS에 넣지 마세요.
- `PRONUNCIATION.md`: 화면의 영문 표기와 원고의 한글 읽기 대응표입니다.
- `rendering-manifest.json`: 렌더링 순서, 입력 TXT, 대응 장표, 저장할 MP3 이름, 원고·파일 해시입니다. 재생 시간은 아직 알 수 없어 `null`로 두었습니다.
- `CONTENT-NOTES.md`: 주요 정정과 출처 확인의 한계입니다.

## 렌더링 순서

1. `rendering-manifest.json`의 `order` 순서로 TXT를 읽습니다.
2. 전체 클립에 같은 한국어 목소리와 속도·샘플레이트 등 설정을 적용합니다. 숫자가 같은 속도 설정이라도 엔진이 다르면 실제 속도가 같지는 않습니다.
3. 첫 클립으로 문장 쉼과 고유명사 독음을 확인한 뒤 나머지를 진행합니다.
4. 결과를 `targetMP3filename`과 정확히 같은 이름으로 저장합니다. 예를 들어 `03-scene.txt`는 `03-scene.mp3`가 됩니다.
5. 각 음원의 앞뒤 누락, 반복·절단, 고유명사, 긴 무음과 클리핑을 확인합니다. 실제 길이는 생성 후 측정합니다.

장 번호와 파일 번호는 항상 같지 않습니다. 9장에 화면이 두 개이므로 `09-scene`은 9장①, `10-scene`은 9장②, `11-scene`은 10장입니다. 오프닝은 `00-opening`, 엔딩은 `31-ending`입니다. 파일 이름을 장 번호로 다시 매기지 마세요.

## 저장소와 연결

장표는 `edu/why-ai-bots/why-ai-bots.html`이며, 검증한 음원의 저장 위치는 그 옆 `audio/`입니다. 기존 MP3는 이전 원고의 보관본으로 남겨 두었고, 이번 원고에 자동으로 재사용하지 않습니다. 새 음원을 넣는 것만으로 기존 보호 설정이 해제되지는 않습니다. 원고와 음원이 맞는지 확인한 뒤 장표의 `PENDING_RECORDING_CLIPS`에서 검증된 클립만 해제해야 합니다. 파일 해시는 내용이 바뀌었는지 확인하는 수단이며, 올바르게 발화했다는 증명은 아닙니다.

원고를 바꾸는 경우 저장소의 HTML 낭독문을 수정하고 `npm run sync`로 생성 파일을 갱신합니다. `npm test`는 텍스트·파일 매핑과 재생기 상태를 검사합니다. 음성 품질·청취·화면과의 실제 동기는 새 음원 생성 후 별도로 확인해야 합니다.

## 시간과 확인 범위

원고만으로 총 재생 시간을 확정하지 않습니다. 실제 길이는 목소리·속도·쉼·렌더링 결과에 따라 달라집니다. 과거 MP3의 실측 길이를 새 원고의 러닝타임으로 사용하지 마세요. 크레딧 배경 음악은 32개 나레이션 클립에 포함되지 않습니다.

이 패키지는 32개 원고의 순서·UTF-8·JSON/문장/텍스트 일치·장표 대응·SHA-256을 자동 검사한 결과물입니다. 음성 생성이나 실제 청취를 완료했다는 뜻은 아닙니다.
